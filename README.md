# Haroon-2.5-HK

مشروع أولي متكامل لبناء نموذج لغوي صغير من الصفر، مع واجهة دردشة ويب عربية متجاوبة وAPI. لا يستخدم أوزان نموذج جاهز.

## تنبيه مهم
هذا المشروع **بنية تشغيل وتدريب قابلة للتنفيذ**، وليس نموذجًا ذا قدرات ChatGPT جاهزة. الأوزان تبدأ عشوائية. ملف `data/train.txt` مجرد مجموعة بداية صغيرة للاختبار، ولن تكفي لإنتاج مساعد ذكي جيد. يجب إضافة بيانات تدريب كثيرة ومرخّصة ثم التدريب والتحقق من النتائج. نموذج byte-level هنا بسيط وعملي للتوافق مع العربية والكود لكنه غير كفؤ مقارنةً بمجزئات حديثة.

## التشغيل محليًا
يفضل Python 3.11 وبيئة فيها ذاكرة كافية.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python train.py --steps 3000
python app.py
```

افتح `http://127.0.0.1:5000`.

## التدريب
أضف نصوصًا كبيرة ومنقحة ومرخصة إلى `data/train.txt`. صيغة محادثة مقترحة:
```
المستخدم: السؤال
Haroon: الإجابة
```
يمكن أن تكون بيانات التدريب نصوصًا تعليمية وأمثلة كود Luau مع شرحها، مع احترام تراخيص البيانات. التدريب الحالي يستخدم توقع البايت التالي، وليس تدريبًا متقدمًا على تعليمات المحادثة؛ لذلك يلزم تحسين البيانات وخط التدريب للحصول على نتائج أفضل.

## نشر Render
1. ارفع المشروع إلى مستودع GitHub.
2. أنشئ Web Service من المستودع على Render، أو استخدم `render.yaml`.
3. تأكد أن ملف الأوزان المدرّب متاح للخدمة. مجلد `checkpoints` مستثنى من Git عمدًا لأن الملفات قد تكون كبيرة. يمكنك رفع الأوزان للمستودع إذا كانت صغيرة ومسموحًا بها، أو استخدام تخزين دائم/مصدر ملفات خارجي، ثم ضبط متغير البيئة `HAROON_CHECKPOINT` إلى مسارها.
4. انشر الخدمة. ملاحظة: PyTorch وحجم الذاكرة قد يجعلان الخطة المجانية غير مناسبة. التدريب لا يُنفّذ تلقائيًا أثناء النشر.

## API
- `GET /api/status`
- `POST /api/chat` with JSON: `{"message":"اكتب سكربت Luau"}`

قبل وجود `checkpoints/model.pt`، ستعرض الواجهة حالة واضحة ولن تدّعي أن النموذج جاهز.

## الأمان والجودة
لا تشغّل كودًا يولّده النموذج تلقائيًا. تحقق من أي كود Roblox قبل استخدامه. أضف حدودًا لحجم الطلبات ومعدلها قبل إتاحة الخدمة للعامة.
